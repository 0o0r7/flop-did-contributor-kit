# CONTRIBUTION_LOG.md

This file records public contributions you post with a DID and the Technocore client.
Each entry is appended by `scripts/contribution_post.py` or can be filled manually when needed.

Template fields for each entry (auto-appended by script):

- Date/time (UTC)
- DID used
- Room/channel
- Sequence (server-assigned `seq`)
- Message hash/ID (if applicable)
- Message text summary
- Full message text (verbatim)
- Problem addressed
- Why this helps ecosystem
- Purpose / value provided
- Outcome / feedback link
- Self-quality score (1-5)
- Related links (public URLs)
- Screenshot/reference (optional)
- Follow-up actions

Keep entries factual, link to public artifacts, and avoid including private keys or passphrases.

---

# Example contribution ideas (high-quality, non-spam)

1. A short, specific bug report with reproduction steps and environment details for the Technocore client or integration.
2. A well-phrased request for clarification about a protocol detail, including a concrete example that shows the ambiguity.
3. A concise tutorial snippet describing how you used a DID to verify a contribution, with a public link to the full article.
4. A translation of an existing helpful guide into another language with a link to the translated article.
5. A short performance observation with data (e.g., latency, error cases) that helps operators troubleshoot.
6. A patch summary announcing a small, useful code change you made with a link to the PR or commit.
7. A reproducible test vector illustrating an edge case in message formatting or normalization.
8. A constructive review or suggestion for documentation that improves clarity for new contributors.
9. A public invitation to collaborators with a clear, limited scope and steps to contribute.
10. A research note linking to a public report, dataset, or experiment relevant to Technocore.

Avoid low-effort posts such as "+1", repeated identical postings across rooms, or promotional spam. Prioritize quality and value to other users.

---

# Contribution quality rubric

Use the following rubric to self-assess contributions. Aim for high-quality (4-5) rather than low-effort posts.

High-quality (4-5):
- Clearly describes a real problem or improvement with reproduction steps or data when relevant.
- Provides actionable suggestions, links to evidence, or a public artifact (PR, issue, article).
- Concise, non-duplicative, and useful to other contributors or operators.

Medium-quality (2-3):
- Some information or data but may lack reproduction detail or a direct public artifact.
- Might be useful but requires follow-up to be verifiable.

Low-quality (1):
- Short acknowledgements without information (e.g., "+1", "thanks"), duplicate posting, or promotion.
- Avoid using this repository to publish low-quality content.
